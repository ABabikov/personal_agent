# Workout Tracker — Implementation Plan

## Phases

### Phase 1: MVP
Формы записи тренировок (зал + плавание) + импорт из Google Sheets + калькулятор калорий + графики.

- [ ] Настройка проекта: Next.js + Supabase + Tailwind + shadcn/ui
- [ ] Схема БД: users, workouts, gym_exercises, swim_series, workout_plans
- [ ] Профиль пользователя: вес, рост, возраст, пол, уровень активности
- [ ] UI: форма записи силовой тренировки (упражнения, подходы, повторы, вес)
- [ ] Авто-расчёт тоннажа (per exercise + total)
- [ ] UI: форма записи плавательной тренировки (серии: дистанция + описание)
- [ ] Авто-расчёт общего метража
- [ ] Калькулятор калорий: BMR (Mifflin-St Jeor) + TDEE + MET на тренировке (зал + плавание)
- [ ] Google Sheets OAuth + импорт истории (зал: парсинг блочного формата, плавание: парсинг серий)
- [ ] Спортивный календарь: обзор всех тренировок
- [ ] Графики: прогресс весов, тоннаж, метраж, калории, вес тела (по времени)
- [ ] TMA layout: адаптивный мобильный интерфейс для Telegram Mini App
- [ ] Web layout: десктопная версия в браузере

### Phase 2: Huawei + Smart Features
Интеграция с часами + предзаполнение + чат-аналитика.

- [ ] Huawei Health OAuth + синхронизация (пульс, калории, длительность тренировки)
- [ ] Кросс-проверка: калории из MET vs калории с часов
- [ ] Предзаполнение следующей силовой тренировки по плану (предыдущие веса + прогрессия)
- [ ] Агентский луп: tools для чтения тренировок, расчёта прогресса
- [ ] Чат-аналитика: "проанализируй прогресс", "скорректируй программу"
- [ ] Katch-McArdle формула (если введён % жира)

### Phase 3: Advanced Analytics
Умные рекомендации + глубокая аналитика.

- [ ] Автоматическое определение плато по упражнениям
- [ ] Рекомендации по корректировке программы на основе прогресса и целей
- [ ] Пульсовые зоны и анализ восстановления
- [ ] Экспорт отчётов

## Data Model

### Gym (силовая тренировка)

```
workouts
  id, user_id, date, type ('gym' | 'swim'), body_weight, total_tonnage, notes

gym_exercises
  id, workout_id, exercise_name, order
  sets: jsonb — [{weight, reps}]  // до 6 подходов
  tonnage: number — авто-сумма (weight × reps) по всем подходам
```

### Swimming (плавание)

```
swim_series
  id, workout_id, order
  distance: number — метры (общая дистанция серии)
  description: text — свободный текст (стиль, интервалы, оборудование, режим)

workouts.total_distance — авто-сумма дистанций всех серий (для type='swim')
```

### Training Plans

```
workout_plans
  id, user_id, name, day_of_week
  exercises: jsonb — [{exercise_name, target_sets, target_reps_range, last_weight}]
```

## Google Sheets Import

### Зал (пн, ср, пт) — парсинг блочного формата
1. Определить блок тренировки по строке с датой
2. Следующая строка — вес тела + номера подходов
3. Далее пары строк: [название + вес по подходам] + [повторы по подходам + тоннаж]
4. Последняя строка блока — общий тоннаж
5. Обработка: два формата дат (DD.MM.YYYY, MM/DD/YYYY), двойные значения веса (28.5/27.1)

### Плавание (вт, чт, сб) — парсинг серий
1. Определить блок по дате
2. Каждая следующая строка — серия: дистанция + описание
3. Суммировать общий метраж

## Technical Decisions

| Decision          | Choice                     | Rationale                                    |
|-------------------|----------------------------|----------------------------------------------|
| Google Sheets     | OAuth 2.0 + google-spreadsheet | Прямой доступ, без ручного экспорта        |
| Калории BMR       | Mifflin-St Jeor            | Самая точная для общей популяции (~82% ±10%) |
| Калории тренировка| MET-метод                  | Стандарт, достаточная точность (±15-20%)     |
| Huawei Health     | REST API напрямую          | Бесплатно, полный контроль                   |
| Графики           | Recharts                   | React-native, TypeScript, гибкие             |
| Swim data model   | distance + description (text) | Простота, свободный формат описания серий  |

## Dependencies

- **External:** Google Sheets API, Huawei Health REST API, OpenRouter (LLM + embeddings)
- **Internal:** Supabase schema, agent loop (Phase 2), user profile

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Huawei Health API ограничения | Phase 2 блокируется | Альтернатива: Terra API как агрегатор |
| Google Sheets блочный формат — сложный парсинг | Импорт ломается | Preview перед сохранением, ручная коррекция |
| Два формата дат в данных | Неверные даты | Авто-определение формата, валидация |
| MET-метод неточен | Калории приблизительные | Показывать как оценку (±15-20%), ручная правка |
