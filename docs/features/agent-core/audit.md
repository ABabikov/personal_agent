# Agent Core — аудит чата (почему «тупит»)

> Аудит проведён 2026-06-04 по коду на ветке `main`. Только чтение; правок логики не вносилось.
> Цель — диагностика качества чата перед рефакторингом под «настоящего тренера».
> План работ: [refactor-plan.md](./refactor-plan.md).

## Метод

Прочитан весь чат-пайплайн: `loop.ts`, `llm/{openrouter,models,embeddings}.ts`,
`memory/{recall,store}.ts`, `prompts/system.ts`, `context/sessionSnapshot.ts`, реестр и
реализации тулов, `features/workouts/gymProgression.ts`, `api/chat/route.ts`,
UI `app/(web)/chat/page.tsx`, доки agent-core. Ссылки `файл:строка` кликабельны в IDE.

## Главный вывод

«Тупость» — не одна причина, а связка. **#1 (обрезка ответа) + #2 (молчаливый даунгрейд
модели) + #3 (пустая память)** дают эффект «отвечает дёшево, коротко и не помнит меня».
Эти три чинятся без смены модели — правится обвязка.

## 🔴 Критичное

### 1. Ответ обрезается на 1024 токенах
`DEFAULT_MAX_COMPLETION_TOKENS = 1024` (`src/lib/agent/llm/models.ts:45`), в `.env` оверрайда нет.
Развёрнутый тренерский разбор не помещается → `finish_reason: "length"` → ответ рвётся на полуслове.
Вероятно, главная причина ощущения недосказанности.

### 2. Молчаливый даунгрейд модели
При статусах `402/404/429/503` или любой ошибке клиент тихо уходит по цепочке
`anthropic/claude-sonnet-4 → openai/gpt-4o-mini → google/gemini-2.0-flash-001 → deepseek/deepseek-chat`
(`src/lib/agent/llm/openrouter.ts:80-188`, `src/lib/agent/llm/models.ts:35-42`).
Если на OpenRouter кончился баланс (402) или alias `claude-sonnet-4` отдаёт 404 — **каждый** ответ
идёт от дешёвой модели. В UI `modelUsed` присутствует, но спрятан в свёрнутом блоке «Tool calls»
(`src/app/(web)/chat/page.tsx:162-175`) — пользователь не замечает подмены.

### 3. Память почти не работает → агент «не знает» пользователя
- `recallContext` стартует с `embedText`; если эмбеддинги падают (402 / OpenRouter не отдаёт
  OpenAI-эмбеддинги) → возвращается `null` → **recall пустой** (`src/lib/agent/memory/recall.ts:137-138`).
- pgvector-RPC `match_chat_messages` **не создан** (`status.md`) → работает брутфорс-фоллбек по
  **300 последним** сообщениям с клиентским косинусом (`src/lib/agent/memory/recall.ts:58-94`).
  Релевантный, но старый контекст не находится.
- **Авто-извлечение фактов не реализовано** (`status.md`). Таблица `user_context` пополняется только
  явным `remember_fact`, а system prompt требует подтверждения перед записью → факты почти не копятся
  → агент каждый раз «с чистого листа».

## 🟠 Архитектура диалога

### 4. Контекст раздувается без границ
`loadConversation` грузит **весь** разговор целиком при каждом запросе
(`src/lib/agent/memory/store.ts:107-122`), и полные JSON-выхлопы тулов переподаются на каждой
итерации ReAct (`src/lib/agent/loop.ts:124-149`). Нет ни обрезки окна, ни суммаризации. При урезанном
лимите токенов это дорого и зашумляет модель.

### 5. Реактивность вместо тренера
`src/lib/agent/prompts/system.ts` — свод правил («сначала спроси подтверждение»), а не характер коуча.
`sessionSnapshot` (профиль + 14 дней нагрузки + 15 фактов) в промпт кладётся, но инструкции быть
проактивным нет — агент не подмечает пропуски/стагнацию/дисбаланс сам.

### 6. Прогрессия примитивная
`progressGymSets` = `+1 повтор`, при `maxReps ≥ 18` → `+вес, reps=12`
(`src/lib/features/workouts/gymProgression.ts:17-30`). Нет периодизации, RPE, deload, привязки к цели.
У плавания методический блок есть (`SWIM_GENERATION_COACH_PROMPT_BLOCK`), у зала — нет.

### 7. Нет сущности «цель»
Цели живут только как свободные факты в `user_context`. Агент не держит структурированную цель и не
сверяет с ней прогресс. Питание (`meal_plan`, снимок localStorage) и тренировки не связаны.
