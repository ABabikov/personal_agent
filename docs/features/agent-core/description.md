# Agent Core — описание

## Problem
Чтобы трекер реально работал как «личный AI», нужен чат-агент, который:
- умеет читать все данные приложения (профиль, тренировки, аналитику),
- умеет писать в БД (новая тренировка, обновление профиля, сохранённые факты),
- помнит прошлые разговоры (контекст между сессиями),
- устойчив к падениям LLM (OpenRouter — это много моделей, любая из них может временно отвалиться).

## Goal
Один эндпоинт `POST /api/chat`, который:
1. принимает текстовое сообщение и conversation_id,
2. собирает контекст (история текущего разговора + семантический поиск по прошлому),
3. крутит ReAct-цикл с tool calling (Claude Sonnet 4 как primary),
4. сохраняет всю переписку в Supabase (с embedding для будущего поиска),
5. возвращает финальный текст + trace всех вызванных тулов.

## User stories
- «Что я делал в прошлый раз в зале?» → агент дёргает `get_last_gym_workout`, отвечает с подходами и весами.
- «Запиши, что я сегодня жим 60×10×4, тяга 70×8×4» → агент парсит, показывает превью с калориями, ждёт подтверждение, вызывает `save_gym_workout`.
- «Сколько ккал я в среднем сжигаю на тренировке?» → агент берёт периодную статистику, делит.
- «У меня болит плечо, запомни» → `remember_fact({key:'injury_left_shoulder', value:...})`, и в следующих сессиях это видно.
- «Динамика моего жима за последние полгода» → `get_exercise_dynamics`, текстовая сводка.

## Data sources
- `chat_messages` (Supabase, миграция `003_chat_memory.sql`) — вся переписка с embedding для семантического поиска.
- `user_context` — пары key/value с фактами про пользователя (явная долговременная память).
- Все таблицы `Workout Tracker` (`workouts`, `gym_exercises`, `swim_series`, `users`) — через тулы.
- OpenRouter API — LLM (`anthropic/claude-sonnet-4`) + embeddings (`openai/text-embedding-3-large`, 1536 dims).

## Non-goals (на этой фазе)
- Streaming ответов.
- Авто-извлечение фактов из сырого диалога (только явный `remember_fact`).
- Тонкая кастомизация системного промпта на UI.
- Голосовой ввод/вывод.
