# Meal Plan & Shopping (питание и список покупок)

## Problem

Домашние приёмы пищи часто однообразны; хочется **вкусных и реально простых** блюд в заданных рамках по КБЖУ, с **понятным планом по дням**, явным **числом порций** и **общим списком покупок**. Цель по калориям и макросам не должна быть «точка в точку»: нужен **коридор**, при этом весь коридор **чуть ниже** ручной «проги» (номинальной цели), чтобы по умолчанию держать лёгкий запас к дефициту. Пользователь должен видеть **расчётный дефицит / профицит** относительно расхода: **средние траты по тренировкам** плюс **импортированные с часов** данные (когда появятся в продукте).

**Операционный дефицит (личная цель):** в среднем по дням держать **дефицит порядка 200–400 ккал** относительно полного расхода (база + активность + тренировки + часы). Это не «максимальный жиросжиг», а **буфер на срывы и дожоры**: плановый средний дефицит остаётся устойчивым, даже если часть дней уходит в небольшой профицит.

## Goal

- План питания **по дням** (календарь или лента дней), в каждом слоте/день: блюдо из рецепта + **количество порций**.
- КБЖУ: **коридор** (нижняя и верхняя граница по ккал и, при необходимости, по Б/Ж/У), причём **весь коридор смещён чуть ниже** заданной вручную номинальной «проги» (уточняется в UI: например верх коридора = прога − X ккал).
- Экран/блок «энергетический баланс»: **средний расход** (база + тренировки + часы) минус **запланированный/фактический приём** → **дефицит или профицит** в ккал; **целевая зона дефицита 200–400 ккал/день** в среднем за период (подсказка «в зоне / ниже / выше» относительно этого коридора).
- Рецепты: **поиск в интернете** (и отбор) — реально **незапарные**, вкусные, попадающие в коридор КБЖУ на порцию или на масштабированную порцию.
- Список покупок: **один общий** на выбранный период плана; **интеграции с магазинами и автозаказы** — отдельная фаза после стабильного MVP.

## Daily Routine Automated

- [ ] Составить план на неделю/период **по дням**, с порциями.
- [ ] Сверить план с коридором КБЖУ и с расчётным балансом (тренировки + часы).
- [ ] Собрать общий список покупок; отметить продукты «уже дома» (базовый набор).

## User Stories

- Как пользователь, я хочу **задать номинальную «прогу»** по ккал/КБЖУ и **ширину коридора**, чтобы система показывала допустимый дневной диапазон **чуть ниже** этой проги.
- Как пользователь, я хочу видеть **дефицит/профицит** в день/неделю с учётом **среднего расхода на тренировках** и **данных с часов**, чтобы план питания был согласован с нагрузкой, и чтобы **средний дефицит попадал в зону ~200–400 ккал** как запас на неидеальные дни.
- Как пользователь, я хочу **планировать по дням** и указывать **число порций** каждого блюда, чтобы неделя была предсказуемой.
- Как пользователь, я хочу **находить в сети** простые вкусные рецепты под мои ограничения, а не только заготовленный каталог.
- Как пользователь, я хочу **управлять питанием из чата** (цели, слоты, база, план порций): спросить, что сейчас настроено, и после согласия **применить изменения** так же, как через UI.

| Source | Type | Access Method |
|--------|------|----------------|
| Ручной ввод «проги», коридора, базовых продуктов | User input | UI + хранение (на старте localStorage, далее Supabase) |
| Тренировки (ккал/длительность/тип) | App DB | Уже есть: `workouts`, калории силовой и т.д. |
| Часы (Huawei и др.) | Импорт / API | По roadmap трекера: см. `docs/features/workout-tracker/huawei-health-integration.md`; до готовности — ручной ввод «доп. расход с часов» или заглушка |
| Рецепты из интернета | Web | Поиск (агент + web_search, парсинг избранных источников, кеш + ручная правка КБЖУ) — детали в `plan.md` |
| **Чат-агент (Jarvis)** | LLM + тулы | `get_meal_plan_state` / `set_meal_plan_state`: снимок `mealPlan` в теле `POST /api/chat` (клиент), ответ `set_*` применяется к `localStorage` — см. `plan.md` раздел «Агент» |
| Каталоги магазинов, заказ | External APIs | Phase 3+ |

## Key Metrics

- Доля дней, у которых запланированные КБЖУ попадают в коридор.
- Средний рассчитанный дефицит/профицит за неделю vs цель.
- Доля рецептов, принятых пользователем без правки КБЖУ после импорта из сети.
